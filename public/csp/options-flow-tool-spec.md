# 期權小學堂 — Options Flow 分析工具 開發需求

## 專案目標

開發一個**純前端、單一HTML檔案**的網頁工具，用於分析從 Barchart Options Flow 頁面下載的 CSV 檔案。使用者上傳CSV後，系統自動解析、儲存於瀏覽器本地，並依「股票代號 + 日期」建立分頁標籤，方便日後切換查看歷史上傳記錄。

**使用情境**：分享給「期權小學堂」社群成員使用，多數人非工程背景，**必須做到「打開HTML檔案就能用」**，不需要安裝Node.js、不需要終端機指令、不需要任何後端伺服器。

---

## 技術限制（重要）

- **必須是純前端**：單一 `.html` 檔案，內嵌所有CSS/JS，雙擊即可在瀏覽器開啟使用
- **不使用任何後端**：不需要Node.js伺服器、不需要資料庫伺服器
- **本地儲存使用 IndexedDB**：取代傳統SQL資料庫角色，資料存在使用者瀏覽器內
- **不需要備份/匯出機制**：使用者自行承擔清瀏覽器快取導致資料遺失的風險，不用額外開發匯出/匯入功能
- **不使用SQLite**：瀏覽器原生JS無法直接寫出 `.sqlite` 二進位格式，若要支援需引入 sql.js (WASM)，增加複雜度且對非工程背景使用者無實際好處，本專案決定不採用

---

## CSV 來源格式說明

CSV來自 Barchart Options Flow 頁面右上角的 download 功能，欄位固定如下：

```
Symbol,Price~,Type,Strike,Expires,DTE,"Bid x Size","Ask x Size",Trade,Size,Side,Premium,Volume,"Open Int",IV,Delta,Code,*,Time,"Exp Type"
```

範例資料行：
```
RKLB,103.96,Call,150,2028-01-21T16:30:00-06:00,584,"36.00 x 358","37.50 x 2",37.5,250,ask,937500,548,2232,91.49%,0.62365489090318,SLFT,N/A,"10:20:33 ET",M
RKLB,103.96,Call,105,2026-06-26T16:30:00-05:00,10,"6.65 x 254","7.00 x 241",7,241,ask,168700,1567,4635,100.29%,0.51157581900093,AUTO,N/A,"10:21:00 ET",W
```

**注意事項**：
- 檔案最後一行通常是說明文字（例如：`Downloaded from Barchart.com as of 06-17-2026 01:36am CDT`），這一行欄位數量會跟標頭不一致，**解析時必須過濾掉**，不可拋出錯誤導致整個解析失敗
- `Bid x Size`、`Ask x Size`、`Time` 欄位內容含逗號或特殊字元，**已用雙引號包住**，CSV解析邏輯必須正確處理含雙引號的欄位（欄位內逗號不應被當作分隔符）
- `Expires` 欄位格式為 ISO 8601（例如 `2028-01-21T16:30:00-06:00`），只需取日期部分（前10個字元）作為到期日顯示
- `Premium`、`Size`、`Strike` 等數值欄位需轉型為數字後才能做加總或排序
- **`Exp Type` 欄位（最後一欄）**：標記該合約是週選或月選
  - `W` = **Weekly（週選擇權）**
  - `M` = **Monthly（月選擇權）**
  - **此欄位可能不存在於舊版CSV**（Barchart曾經的下載格式沒有這一欄），解析時須做容錯處理：若該欄缺失，視為 `未分類`（不可因缺少這欄而解析失敗）

## 功能需求

### 1. CSV 上傳功能

- 提供檔案上傳按鈕（`<input type="file" accept=".csv">`），或支援拖拉檔案到指定區域上傳
- 上傳後立即在前端用JavaScript解析CSV（純手刻parser即可，不需要外部套件，需正確處理雙引號欄位）
- 解析失敗（格式不符）時，顯示清楚的錯誤訊息給使用者，不可讓整個頁面當掉

### 2. 自動建立分頁標籤（Tab）

- 從CSV內容自動取得：
  - **股票代號**：取自CSV的 `Symbol` 欄位（每一行的Symbol應該一致，取第一筆有效資料的值即可）
  - **日期**：取自CSV的下載說明那一行（`Downloaded from Barchart.com as of 06-17-2026...`），或者如果該行不存在/格式不同，改用**使用者上傳當天的日期**作為fallback
- 分頁標籤文字格式：`{股票代號} {YYYY/MM/DD}`，例如：`RKLB 2026/06/17`
- 每次上傳新的CSV：
  - 若「股票代號+日期」組合**已存在**（使用者重複上傳同一份資料），則**覆蓋舊資料**並提示使用者「已更新此標籤的資料」
  - 若「股票代號+日期」組合**不存在**，建立一個新分頁標籤，並自動切換顯示到這個新分頁
- 分頁標籤可以左右橫向排列，標籤數量多時可以橫向滾動或自動換行（依實際畫面美觀程度決定，不強制規定）
- 點擊任一分頁標籤，下方內容區切換顯示該分頁對應的資料分析結果
- 分頁標籤旁可以加一個小的「×」按鈕，允許使用者刪除該分頁（連同IndexedDB中的資料一併刪除），刪除前需要二次確認（例如 `confirm()` 彈窗）

### 3. 資料分析內容（每個分頁內顯示）

每個分頁顯示時，需包含以下分析區塊（沿用之前 Node.js 版本 `analyze-options-flow.js` 的邏輯，移植成瀏覽器JS）：

#### 3.1 整體摘要
- 總交易筆數（Call筆數 / Put筆數）
- Call 總權利金（Premium加總）
- Put 總權利金（Premium加總）
- Call/Put 權利金比值

#### 3.2 單筆交易明細（前十筆）
- 依**該筆交易的Premium**由大到小排序
- 顯示欄位：Type、Strike、Expires、Trade（成交價）、Size、Side、Premium、Time
- 用表格呈現，金額格式化為 `$1,234,567` 形式

#### 3.3 依到期日排序統計（前十筆）
- 將資料依 Type + Strike + Expires 分組（同一個合約多筆交易視為一組）
- 統計每組的：交易筆數、總Size（張數）、總Premium
- 依到期日由近到遠排序，顯示前十組
- 用表格呈現

#### 3.4 不分到期日，依總Premium排序（前十筆）
- 同樣依 Type + Strike + Expires 分組
- 但這次依**總Premium**大小排序（不分到期日），顯示前十組
- 用表格呈現，標示為「最大資金押注」

#### 3.5 到期日清單
- 列出本次CSV資料涵蓋的所有不重複到期日，由近到遠排列

#### 3.6 週選（Weekly）vs 月選（Monthly）統計

依 `Exp Type` 欄位（W/M）將整批交易拆成兩組，分別統計：

- **整體摘要**（同3.1邏輯，但分別針對W組與M組各算一次）：
  - 該組總交易筆數（Call筆數 / Put筆數）
  - 該組 Call 總權利金、Put 總權利金
  - 該組 Call/Put 權利金比值
- 用左右並排或上下分區的方式呈現「週選統計」與「月選統計」兩個區塊，方便比較
- 若CSV缺少 `Exp Type` 欄位（舊格式相容），則此區塊顯示「本次資料無到期類型標記，略過週選/月選統計」，不可報錯

**呈現目的**：讓使用者快速判斷當天大單資金是集中在近期到期的週選（短線、投機性較高），還是月選（中長線、機構持倉較常見的標準到期日），這兩種類型的籌碼性質不同，混在一起看容易誤判。

#### 3.7 篩選器：依到期類型切換顯示

在分頁內容區上方，提供一個簡單的篩選控制（例如三個按鈕或下拉選單）：

- **全部**（預設，顯示所有資料）
- **僅週選（W）**
- **僅月選（M）**

切換篩選器時，3.2～3.4的「單筆交易明細」「依到期日排序」「依總Premium排序」三個表格都應該**即時依篩選結果重新計算並顯示**，不需要重新整理頁面或重新上傳CSV。

## IndexedDB 資料結構建議

- 建立一個 Database（例如命名為 `OptionsFlowDB`）
- 建立一個 Object Store（例如命名為 `uploads`），結構建議：

```javascript
{
  id: "RKLB_2026-06-17",        // 主鍵：股票代號_日期，用於判斷是否已存在/需覆蓋
  symbol: "RKLB",
  date: "2026-06-17",
  uploadedAt: "2026-06-17T10:30:00",  // 實際上傳時間戳記
  rawRows: [...],                // 解析後的原始資料陣列（每筆交易一個物件，包含expType欄位：'W'/'M'/'未分類'）
}
```

- 頁面載入時，從IndexedDB讀取所有已存在的 `uploads`，自動還原所有分頁標籤
- 分析結果（單筆明細、分組統計等）**不需要**另外存入IndexedDB，每次切換分頁時用`rawRows`現場計算即可，避免資料重複或不同步

## UI/UX 建議（不強制，可依實際開發調整）

- 整體風格簡潔、表格易讀即可，不需要過度設計
- 上傳區域放在頁面上方，分頁標籤列在上傳區域下方，內容分析區在最下方
- 表格中 Call 用綠色系標示、Put 用紅色系標示，方便快速辨識（可選，非必要）
- 週選（W）/月選（M）可用不同顏色的小標籤（Badge）標示在每筆交易旁，方便一眼辨識
- 數字金額一律加千分位逗號，並加 `$` 符號
- 頁面標題可以掛 `期權小學堂 - Options Flow 分析工具`

---

## 不需要做的事（避免過度開發）

- 不需要使用者帳號/登入系統
- 不需要雲端同步
- 不需要備份/匯出/匯入功能
- 不需要支援多檔案同時上傳（一次一個CSV即可）
- 不需要圖表視覺化（純表格呈現即可，除非後續另外提需求）
- 不需要支援CSV以外的格式（例如Excel）
